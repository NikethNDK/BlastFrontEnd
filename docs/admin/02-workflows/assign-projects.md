# Assign projects

## When to use this

- After registering a new user.
- When someone should work on additional (or different) projects.
- When a researcher’s Request form shows no projects.

## Rule

Projects live on the **employee assignment**, not on the login form.

Login: who they are and which labs.  
Assignment: which **project codes** they own.

## Steps

1. Confirm the project is **active** in Project Management.
2. Confirm the **login** exists with the correct lab + role.
3. Open **Employee Project Management**.
4. If they have no row yet: **Assign employee** (employee ID, lab, role, username, projects).
5. If they already have a row: use the update action if available in your build; otherwise follow your lab’s process (do not reuse Employee ID on a second assign — it must be unique).

Username in the assign modal only appears after lab **and** role match the login.

## Researchers and managers together

A researcher request also needs a **manager who shares at least one project**. Assign the manager to the same project codes (or a superset) or the project dropdown stays empty (“No common projects between researcher and selected manager”).

Lab assistants on that form are filtered by lab + selected project as well.
